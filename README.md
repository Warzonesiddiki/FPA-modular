# FPA-modular — FP&A Month-End Copilot (attempt #5, planned as the final one)

One analyst. One tool. The whole month-end: pull the month straight from Dynamics 365 (read-only) or import messy ERP exports → validated, balanced books → statements, budget-vs-actual and KPIs → 28 exception rules with an owner inbox and a suggested fix on every finding (plus a rectification journal file for the ERP) → close checklist and reconciliations → rolling forecast, scenarios and integrated planning → board-ready Excel + PowerPoint + PDF. Offline, local-only, every number drillable to the source file and row. AI (optional, off by default) drafts commentary around verified numbers — it never computes one.

## How this repository is built
The design is complete in `docs/` (91 numbered specifications plus the plan of record). **One builder agent** executes it (DEC-007, `docs/17` §4):

| File | What it is |
|---|---|
| **`AGENT_PROMPT.md`** | The single operating prompt for the builder: session protocol, work-item loop, spec-gap rules, non-negotiables, self-verification, handover format. If a tool needs the prompt under another name (`AGENTS.md`, `CLAUDE.md`), copy this file — never fork its content. |
| **`docs/WORK_PLAN.md`** (+ `.csv`) | The sequenced build: 266 work items in milestones M0–M6, each with mission, dependencies (WI ids), acceptance criteria, paired test and the spec sections to read. Generated by `tools/generate_work_plan.py` — edit the generator, never the output. |
| **`TASKBOARD.md`** | Live ledger: status and evidence per work item, questions for the owner, current position. |
| **`docs/00_INDEX.md`** | Document map, source-of-truth matrix (who wins on conflict), current phase (§10). |
| **`docs/MASTER_PLAN.md`** | Why attempts 1–4 died and how this plan prevents each cause; product, architecture, milestones, gates. |
| **`audit/BRUTAL_AUDIT_PASS3_2026-10-14.md`** | The current audit of the documentation set (supersedes the three earlier audit files). |
