# 83 — PILOT PLAN

**Selection:** one friendly company, single currency, one analyst + CFO sponsor, ERP export access, close pain measurable (current cycle days + hours baseline recorded). **Setup:** questionnaire (58) → settings/DEC → opening + 2 historical months loaded → parallel run (82). **Duration:** 3 closes (hypercare). **Success criteria (agreed before start, measured at 84):** close cycle days ↓ ≥40% by close 3; analyst hands-on ≤ 30–60 min/close (14 §6); zero S1; every pack number spot-tied in CFO review; findings workflow used (≥80% findings actioned in-app, not side-channel); analyst M1 pass. **Data protocol:** client data stays on client machine (76/78); support via diagnostics/anonymised extracts. **Exit/convert:** success → commercial licence (79) + case-study permission ask; miss → honest review: fixable (backlog DEC) vs fit problem (stop, learn, document in 84) — a pilot that "succeeds" by lowering bars is attempt-#5 behaviour and is named as such here.


## Pilot operating rhythm
Week 0: questionnaire (58) + training M1 (59). Weeks 1–2: two historical months loaded, mapping profiles built, parallel-run setup. Closes 1–3 under hypercare (doc 82): support on call, defect log reviewed after each close, threshold changes only by DEC. After close 2: go/no-go to retire the spreadsheet to backup. End: doc 84 review 30 days after close 3, conversion decision, and lessons appended to RESEARCH_AND_LESSONS — win or lose (the institutional memory attempts 1–4 kept losing).
