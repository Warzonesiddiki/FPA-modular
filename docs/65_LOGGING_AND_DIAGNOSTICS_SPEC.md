# 65 — LOGGING & DIAGNOSTICS SPECIFICATION

1. **Format:** JSON lines, local files only under project `logs/` (app.log, jobs.log, ai.log): `ts, level, module, job_id?, code?, msg, ctx{}`. Levels DEBUG(dev builds only)/INFO/WARN/ERROR. **Redaction filter (tested):** amounts, account names, vendor names, descriptions, keys, and file contents are never logged at INFO+; DEBUG may log counts/ids/hashes only — financial values stay out of logs entirely, by rule, so logs are always shareable.
2. **Rotation:** 5MB × 5 files per log; no upload ever (12).
3. **Diagnostics bundle (S15/S13):** zip = app/OS versions, schema version, redacted logs (last 7d), DB integrity + audit-verify results, settings keys (values only for non-sensitive), file hashes of last exports, this spec's manifest checklist — generated by `app/desktop` diagnostics routine with a pre-download preview listing every included file. A test asserts the bundle contains no gl amounts by scanning against known fixture values.


## Event catalogue (minimum INFO events; module → event → key ctx fields — ids/hashes/counts only)
api: request.completed {route, status, ms} · jobs: job.started/finished/failed {job_id, type, duration_ms, counts} · imports: batch.staged/committed/superseded/quarantined {batch_id, counts} · rules: run.completed {run_id, per_rule_counts} · exports: report.generated/blocked {report_id, kind, checks_failed[]} · security: audit.verify {result, rows} licence.checked {type, result} · errors: app.error {code} unhandled {diagnostics_id}.
Diagnostics id format: `diag-<yyyymmdd>-<8 hex>` shown in ERR-099 and stamped into the log slice so a user report and the bundle always join up. Log review is part of AUD-D/K: any fixture financial value found in logs (scripted scan against known corpus values) is an S1 privacy defect.
