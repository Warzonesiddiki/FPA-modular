# 19 — DETAILED FUNCTIONAL SPECIFICATION (FR Register)

> Every functional requirement in the product, numbered. Each FR: statement / inputs / processing rule / output / error / screen / API / test. PRD (01) owns scope; this doc owns behaviour detail; any FR not here must not be built.

## A. Projects & periods (FR-PRJ)
- **FR-PRJ-001 Create project** — name, currency, FY-start, calendar → project folder + DB + default thresholds (07), default COA template (28). Duplicate name in same parent → ERR-010 with rename hint.
- **FR-PRJ-002 Sample project** — generated by the corpus generator, flagged `is_sample`, deletable, never mixed with real data.
- **FR-PRJ-003 Period lifecycle** — periods auto-created for FY; states open→closing→locked (23); lock blocked by open high findings unless override+note (audited); unlock requires note; locked period rejects imports (EXC-005).
- **FR-PRJ-004 Backup/restore/delete** — per 12 §2/§7; restore verifies SHA + audit chain before open; delete requires typed name.

## B. Master data (FR-MDM)
- **FR-MDM-001 CRUD** entities/accounts/cost-centres/vendors/owners with code uniqueness per project (ERR-050), deactivation (never delete once referenced).
- **FR-MDM-002 Account metadata** — account_type, statement_line, normal_side, tags (`suspense|accrual|contra|depreciation|cash|receivables|payables|inventory|debt|equity`), owner assignment with validity.
- **FR-MDM-003 Import master data** from CSV with same quarantine discipline as doc 06; unknown-code resolution flow during GL import creates master rows only with analyst confirmation.

## C. Import (FR-IMP-001…012, detail doc 06)
File stage → profile → suggest/map → transform → validate/quarantine → control totals → atomic commit → TB gate → overlap report. Re-import replaces; mapping profiles versioned; every stage state visible and resumable; malformed corpus expectations are FR-level tests.

## D. Statements & analysis (FR-CAL, detail doc 03)
- **FR-CAL-001** PL/BS/CF generation with presentation-sign map. **002** KPI library (29 §KPI catalogue: ≥30 KPIs defined). **003** BvA at lowest shared grain with favourable logic + AND-materiality. **004** Bridge (volume/price/mix/other) only with drivers. **005** Drill to row. **006** YTD/YoY/MoM. **007** Data-quality score per period (29 §DQ: completeness, balance, mapping coverage, stale masters, % manual journals → 0–100 with deductions table; shown S01; never blocks, always explains).

## E. Close management (FR-CLO, detail doc 30)
Close calendar (business-day aware), task checklist (template + per-period instances, owner, due, dependency, evidence link), blockers computed from real system state (TB unbalanced, high findings open, forecast stale, exports not generated), close meeting pack = Excel+PPT of that period. Sign-off record per period (analyst attestation text + timestamp → audit).

## F. Budgeting & planning (FR-PLN, detail doc 29)
Budget versions import/author-lite (grid edit of imported budget with full audit), approval states, budget phasing, driver planning (volume/price/headcount/rate/custom), headcount plan (joiners/leavers, cost = HC × avg cost × (1+increment%)), capex plan → depreciation schedule (SLM/WDV, useful life), debt schedule (draw/repay, interest = avg balance × rate), working-capital plan (DSO/DPO/DIO targets → BS forecast), 13-week cash forecast (weekly granularity from AP/AR/debt/payroll calendars), integrated 3-statement forecast linkage (PL→BS→CF must balance in forecast too — imbalance is a check failure, never plugged silently).

## G. Exceptions (FR-EXC, detail doc 07)
24 rules, run on demand + auto after commit (setting), findings inbox, owner/due workflow, waivers with expiry, re-run verification, exportable owner action list (Excel, per owner), escalation digest (in-app; email only via exported file in v1 — no SMTP credentials stored).

## H. Forecast & scenarios (FR-FOR, detail docs 08 + 29)
8 methods, backtest selection, FVA, rolling refresh, scenarios (driver/%/absolute deltas), **sensitivity** (one/two-variable tables over a driver, step/range analyst-set), **goal seek** (solve driver value for target KPI via bisection on the deterministic model, 50 iterations, tolerance minor-unit; no-solution reported, never faked), **what-if sandbox** (unsaved delta overlay on charts; saving converts to scenario).

## I. Reconciliations (FR-REC)
Subledger-to-GL: bank extract vs cash accounts, AR/AP subledger totals vs control accounts, payroll summary vs salary accounts — matched by amount/date/reference scoring, unmatched lists both sides, tolerance setting, recon sign-off per period. (v1: file-based, same import pipeline; source_kind `subledger`.)

## J. Reporting (FR-RPT)
Excel (09), PPT (10), PDF, **report builder**: analyst picks statement/BvA/KPI blocks + period + grain into a saved report definition (versioned) → renders to Excel/PDF identically to fixed packs; **KPI builder**: formula over existing KPI/account aggregates using a safe expression grammar (no arbitrary code; operators +−×÷, brackets, defined names; tested against fixtures; result becomes a KPI usable everywhere). Board pack = Excel+PPT+PDF generated in one action from one snapshot.

## K. Alerts (FR-ALR)
Threshold alerts on KPIs/findings/forecast-bias (doc 08 §6), in-app alert centre (S01 bell + list), dedupe by (alert_key, period), digest view, 90-day retention, no external push in v1.

## L. AI (FR-AI, doc 11) · M. Audit/security/settings (FR-GOV, docs 12/23) · N. Help/diagnostics (doc 18)
As specified in their owning docs; every FR-GOV mutation writes audit; settings changes show impact text before save.
