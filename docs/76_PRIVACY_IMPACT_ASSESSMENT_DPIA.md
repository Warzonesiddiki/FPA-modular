# 76 — PRIVACY IMPACT ASSESSMENT (DPIA)

Data processed: financial transactions; names that appear inside them (vendors, customers, employees in payroll extracts, finding owners' names/emails-optional). Purpose: internal FP&A only. Lawful basis: the customer's own legitimate business use — the vendor (us) receives **no data by design** (offline, no telemetry, 12); support data flows are user-initiated files only (diagnostics value-free, anonymised extracts per 78). Minimisation: AI payloads aggregate-only (11 §4); logs/diagnostics redacted (65); descriptions never sent anywhere by default. Retention: user's project folder, user-controlled deletion (12 §7); waivers/audit retained while project exists (integrity purpose, disclosed). Risks & mitigations: Dynamics 365 connector (DEC-013) → read-only, user-initiated, TLS to Microsoft/customer hosts only, tokens in the OS keyring, no background pulls, Disconnect wipes credentials (12 §1(d)/§5, 25); local device compromise → OS encryption guidance (18); over-sharing exports → advisory stamps + share-guidance (70); AI enablement → explicit consent copy naming what leaves the machine (aggregates + labels) in S13. Data-subject requests are the customer-employer's process; the app supports them via drill/export of the person's rows (a support runbook note in 35). Review trigger: any feature adding network, accounts, or new personal-data categories reopens this DPIA before build (DEC required).


## Data inventory
| Data | Source | Stored | Sent anywhere? |
|---|---|---|---|
| Employee names in payroll descriptions | ERP export | gl_rows.description (local) | No — AI payloads exclude descriptions (doc 11 §4) |
| Vendor/customer names | GL + masters | local DB | AI commentary may include vendor names for material variances (disclosed in S13 consent) |
| Owner names/emails | Analyst-entered | owners table | Never (no email sending v1) |
| Analyst label | Local setting | audit_log | Never |
| Microsoft sign-in identity (UPN) and OAuth tokens — Dynamics 365 connector (DEC-013) | Entra ID, on the analyst's own sign-in | UPN shown in S13 and kept in `connector.*` settings; tokens only in the OS keyring (never DB/logs/backups) | Only to `login.microsoftonline.com` and the customer's own Dynamics 365 host, over TLS, when the analyst clicks; the vendor receives nothing |
| Ledger rows read from Dynamics 365 | Customer's tenant | Snapshot workbook under `imports/` (same retention as any import original, `privacy.store_import_originals`) + gl_rows | No (same as file imports) |
The connector does not change the controller/processor position: data moves from the customer's Dynamics 365 tenant to the customer's own computer under the customer's own Microsoft identity; Microsoft's processing terms for Dynamics 365/Entra ID already apply to that tenant. The client is data controller; the vendor receives no data by design (support = user-sent diagnostics/anonymised extracts, docs 65/78). This controller/processor fact must be stated precisely in doc 80's legal pack.
