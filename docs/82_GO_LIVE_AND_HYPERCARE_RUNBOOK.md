# 82 — GO-LIVE & HYPERCARE RUNBOOK

**Preconditions:** doc 16 §4 release checklist signed; pilot plan (83) if first client; training M1 scheduled (59); backups of any predecessor process (the spreadsheet pack) archived read-only.
**Go-live sequence (day):** install on analyst machine (fresh, not the dev build) → restore/verify or create project → opening balances import + TB → parallel-run month: in-app pack vs existing spreadsheet pack compared line-by-line (Checks + a signed comparison note; differences explained as app-correct/spreadsheet-error/data — each logged) → owner accepts parallel run (DEC) → spreadsheet retired to archive (never deleted at go-live).
**Rollback triggers:** any S1 (wrong number reaching a pack, data loss) → stop, revert to spreadsheet process for that month, S1 process (72) before second attempt. Rollback is a normal outcome, rehearsed in UAT-09/11 — not a failure of nerve.
**Hypercare (first 3 closes):** support on call during close window; daily check-in first close, per-close review after; defects triaged same-day (S1/S2); close cycle days tracked vs baseline (84 metrics); exit criteria: 3 consecutive closes with no S1, cycle time ≤ agreed target, analyst passes M1 competency (59) → move to standard support (35).
