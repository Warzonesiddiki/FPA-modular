## 4. Decision log (DEC) — append-only
- **DEC-001** Stack Python + FastAPI + SQLite + React (doc 04 ADR-001…008).
- **DEC-002** Windows-first, single-user, offline v1.
- **DEC-003** 24-rule catalogue with canonical finding keys (doc 07 §2). *(Extended to 28 by DEC-011.)*
- **DEC-004** Coherent corpus + planted acceptance as the release gate (docs 42, 14 §3).
- **DEC-005** AI edge-only / off by default (doc 11).
- **DEC-006** 2026-10-14 (owner, auto-decision mode): docs 00–88 baselined; Wave 1 build authorised on the multi-agent model. **Superseded in part by DEC-007** — the build was paused after Wave 1a/1b (core/money, calendar, errors, schema v1, 9 tests) and the "remediation verified 9/9" claim is withdrawn by audit pass 3.
- **DEC-007** 2026-10-14 (owner): **single-agent execution model.** The 500-agent packet model (317 creator + 317 tester prompts, file-disjoint waves, integrator role) is retired. One builder agent executes `docs/WORK_PLAN.md` (241 work items at DEC-007, 250 since DEC-011/012; milestones M0–M6, generated by `tools/generate_work_plan.py`) under `AGENT_PROMPT.md`, keeps `TASKBOARD.md`, and performs the tester/auditor roles itself through the self-verification protocol and milestone audit sessions. `agent-prompts/`, `tools/generate_agent_packets.py`, `docs/FILE_MANIFEST.*` and `docs/DEPENDENCY_GRAPH.*` are deleted; docs 33, 34, 85, 86, 91 and MASTER_PLAN §7–§12 are rewritten accordingly. Rationale: the owner now runs one most-capable agent; the multi-agent apparatus was 636 files of coordination overhead with its own defects (BLOCKED-and-wait semantics that a sole agent cannot use, prose dependency links, duplicated contracts).
- **DEC-008** 2026-10-14 (builder; **accepted** under DEC-010; bars since raised by DEC-011 to 36/36 · 0/13 · 19/19): **acceptance bars corrected.** Recall 32/32 (was "≥ 29/31"), controls 0/10 (was 0/8; two one-leg controls added per AND-rule), High 18/18 unchanged but now enumerated; P30 converted from an undefined "control" into a real EXC-018 Medium plant that tests the escalation boundary. Rationale: the corpus is self-authored, so any missed plant is a defect; the old controls (both legs failing) could not distinguish an AND from an OR implementation — the exact attempt-#4 bug. Docs 14 §3, 42 §7–§8, 07 §4/§6, 03 §5 changed in one commit.
- **DEC-009** 2026-10-14 (builder; **accepted** under DEC-010; ERR-046 added by DEC-011 → 64 codes): **error catalogue extended** from 24 to 63 codes (doc 22) so every FR in doc 19 has a defined failure; ERR-025 introduced for bad amounts (money.py's reuse of ERR-021 was a defect); HTTP status mapping fixed in doc 05 §1.

- **DEC-010** 2026-10-14 (owner): **auto-decision mode.** The owner delegates every pending and future product/engineering decision to the builder: "auto take best decision". Effects: DEC-008 and DEC-009 are accepted; OQ-06, 07, 11, 12, 13, 14 are closed with their defaults; from now on a class-A gap (`AGENT_PROMPT.md` §4) is decided by the builder, recorded as `DEC-nnn (auto)` with the alternatives considered and the reversal cost, and work proceeds **without waiting**. The owner may reverse any auto-decision later; the builder keeps reversals cheap by isolating decided behaviour behind settings or single-owner modules where the cost is low. The *Owner attention* block in TASKBOARD becomes informational (what was decided, where), never a queue. Decision quality rule: choose what the best all-in-one FP&A tool would do for this owner's workflow (doc 01 §3 P1), not the cheapest option.
- **DEC-011** 2026-10-14 (auto): **entry-hygiene rules + rectification suggestions.** The owner's stated duty — "highlight the abnormal or wrong entry passed and suggest rectification" — becomes first-class: rules EXC-025 account–narration mismatch, EXC-026 amount outlier / decimal-shift suspect, EXC-027 unusual cost centre, EXC-028 near-duplicate vendor charge (doc 07 §3, doc 44); EXC-012 generalised to contra-normal postings; **every finding carries a `suggestion`** built from a per-rule template (doc 07 §7, closed kind list, balanced lines, confidence, basis sentence), consumable as a doc-39 `correction_view` adjustment or queued into a **rectification journal file** in the ERP's import shape (doc 26 §7; the app never posts); a verification loop proposes `corrected → verified` when the correcting lines come back in the GL. Corpus: plants P33–P36, controls C11–C13 → bars 36/36 · 0/13 · 19/19 (doc 14 §3, doc 42); FR-EXC-012…015, FR-IMP-016…019; ERR-046; schema v2 deltas 10–12 (doc 02 §7); settings in doc 62. Alternatives considered: (a) suggestions only for the four new rules — rejected, the inbox must be a work list for every finding; (b) ML anomaly scoring — rejected for v1 (explainability, determinism; stays in the backlog as before); (c) posting corrections to D365 via OData — rejected (write-back by API is a "never" in doc 01 §4; the file path keeps the accountant's review and the ERP's own controls). Reversal cost: low — rules are isolated modules, suggestions are a single module + two columns, the journal export is one exporter.
- **DEC-012** 2026-10-14 (auto): **Dynamics 365 first-class source.** The owner's ledger is in Dynamics 365 and today's workflow is "Voucher transactions → Excel → everything by hand". Doc 26 §5 now specifies the F&O (Voucher transactions, Vendor transactions, Trial balance, Budget register) and Business Central (G/L Entries, G/L Budget Entries, Trial Balance) shapes as presets that map with zero edits; doc 06 gains the `split:` (segmented `Ledger account`, raw string kept in `source_account_ref`), `conditional:` and `constant:` transforms, posting-layer scope (`OUT_OF_SCOPE_LAYER`), per-account trial-balance tie-out (`tb_check`) and AP→GL vendor enrichment; the sample corpus ships the golden period in these shapes with a parity test (doc 42 §4, doc 14 §3). Other ERPs keep their presets; nothing D365-specific enters calc, rules or exports beyond the journal format. Alternatives: a live OData connector — Phase 2 as before (doc 17 §5), and it must land through the same pipeline. Reversal cost: nil (presets are data; the transforms are generic).

## 6. Change control
Spec changes after the Phase-0 freeze: one commit editing the owning doc (doc 00 §5) + every doc that repeats the fact + `docs/CHANGELOG.md` + a DEC entry here when scope/contract-affecting; if the change alters a work item, `tools/generate_work_plan.py` is edited and `docs/WORK_PLAN.*` regenerated in the same commit. Code follows in a separate commit. Emergency fixes follow the same path — there is no "code first, docs later" lane (`AGENT_PROMPT.md` §4-B).
