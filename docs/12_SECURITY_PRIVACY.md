# 12 — SECURITY & PRIVACY SPECIFICATION

> Owner of: local-only guarantees, data protection, hostile-input handling, supply chain. Posture: the app's promise is "your financial data never leaves this laptop" — any feature breaking it is a release blocker.

## 1. Data & network guarantees
All data in the project folder (doc 04 §5). Network: (a) API binds 127.0.0.1 only, ephemeral port, per-launch token required: the desktop shell generates a random 32-byte token at startup, passes it to the API process via environment variable, and injects it into the served UI's in-memory config (never to disk, never in a URL); the UI sends it as `X-FPA-Token` on every API request and the API rejects requests without it (constant-time compare, 401/ERR-006); the sole browser callback exception and CORS-preflight handling are specified in §1.1; CLI reads the token from a 0600-permission runtime file in the project folder written by the shell; CORS locked to the local UI origin; (b) AI calls only when enabled (doc 11); (c) no telemetry, analytics, crash upload, or update phone-home in v1 (update = manual installer download); (d) **Dynamics 365 connector** (doc 26 §8, DEC-013) egress only when `connector.enabled` is true **and** either a user-initiated job is running or an explicit foreground sign-in/test/profile-check action is active (DEC-016; never triggered by polling), only over TLS (certificate verification cannot be disabled), and only to the allow-list — `login.microsoftonline.com`, the configured `connector.base_url` host (which must end in `.operations.dynamics.com` or equal `api.businesscentral.dynamics.com`, or be a customer-named host the owner explicitly accepts in S13 with a warning), plus `127.0.0.1` for the sample project's local demo ledger only; the allow-list is enforced inside `connectors/transport.py` on every request *including redirects* (ERR-113) and the connector never calls the ERP in the background. A CI test greps for outbound-call libraries/URLs outside the AI client and connector allowlists; the socket-blocked full run (§8) executes with the connector disabled and must observe zero connection attempts.

### 1.1 Local HTTP authentication and OAuth callback (DEC-016)
Every `/api/v1` operation, including health, downloads, project lists and job polls, requires `X-FPA-Token`. A missing/incorrect token gives HTTP 401 / ERR-006 before reading any project, resource or job. Non-callback requests must use the shell's exact loopback authority (`Host`, including assigned port); a present `Origin` must exactly equal the served UI origin, never `null`, a wildcard, a sibling port or a suffix match (403 / ERR-007). CLI requests may omit `Origin` but not the token. `X-FPA-Project` selects the project for every project-scoped request and must match any path/body/query project id and every referenced resource; foreign/missing ids yield ERR-001 without disclosing foreign state. The token is not a cookie; CSRF through ambient credentials is impossible. Downloads use authenticated fetch, not a token-bearing URL.

OPTIONS is transport negotiation, not a data endpoint: no token value is required for a preflight, but authority, exact Origin, requested registered method/path, and requested-header allow-list are all checked. A valid preflight returns 204 with no data; an invalid one returns 403/ERR-007 without CORS permission. Normal CORS headers are sent only for the exact approved UI origin. No endpoint permits arbitrary-origin credentialed access.

The **only application-data exception** is `GET http://localhost:<assigned-port>/connector/callback` at the root, **not** under `/api/v1`. It accepts no API token or project selector from the browser. It requires a cryptographically random 32-byte state, bound in memory to one token-authenticated sign-in attempt, its project, tenant/client, exact redirect URI and S256 PKCE verifier. The attempt expires **300 seconds** after creation (injected clock); a new attempt invalidates the previous pending attempt for that project. The callback verifies exact loopback authority and state, atomically consumes the pending attempt **before** one code exchange, and rejects missing/wrong/expired/replayed state before any outbound call. No persistent secrets/state, open redirects, or project selection from callback parameters. A valid provider-denial response consumes state but does not exchange a code. An invalid callback returns 400 and a fixed, escaped HTML failure page; a successful exchange returns 200 and a fixed close-tab page. Neither page echoes query fields. The authenticated UI sees a redacted ERR-111 through `ConnectorStatus.last_auth_error`; no code, state, verifier, token, secret or raw query enters logs/audit/jobs/diagnostics. Host/origin checks for this narrow callback use the registered localhost redirect rather than the UI's potentially different loopback hostname. It is an explicitly initiated sign-in operation, never background network. CSP `default-src 'none'`, `Cache-Control: no-store`, `Referrer-Policy: no-referrer` on both pages. Token-shaped authorization credentials are never exposed as response data; the authorize URL itself is the one permitted short-lived PKCE/state URL.

## 2. At-rest protection
Project folder inherits OS user permissions (documented in doc 18 with a "store on an encrypted drive" recommendation). Optional project passphrase (Settings): DB encrypted via SQLCipher-compatible layer **only if** the dependency clears the tech budget (doc 04 §6) — otherwise v1 ships OS-permission posture honestly labelled in UI, and passphrase encryption is a Phase-2 ADR. Never claim encryption we don't ship (attempt-#4 truth rule). Backups are copies of the same folder; restore verifies hashes + audit chain before opening.

### 2.1 Confirmed project deletion and retention (DEC-018)
DELETE in doc 05 §7.2 requires the exact name, latest metadata version and idempotency key. Reject active/queued jobs and active foreground I/O/read/write leases with ERR-092 before effects; acquire an exclusive lifecycle lease so a new job or callback cannot race admission. An idle pending OAuth attempt is invalidated on accepted deletion; late callbacks cannot repopulate a deleted project's keyring. Revoke **only that project's** connector/MSAL and project-scoped AI keyring entries, never global environment variables or another project's entries. A failed keyring write must not return success or silently leave credentials usable; ERR-093, durable intent and retry/recovery guidance (sign-in may already be cleared, financial files preserved until move).

Persist a crash-recoverable deletion intent outside the target folder before irreversible work. After revocation, atomically rename the registered folder into a private same-volume trash sibling (`.fpa-trash/<project_id>/<deletion_id>`); never use the displayed name as a path. Refuse symlink/reparse-point substitution and do not follow links while moving/purging. Mark the project inaccessible during finalisation; publish 200 only once move, active-catalogue removal, app-level audit and receipt are durable. On restart, finish an accepted durable intent exactly once, or keep it inaccessible with an actionable write failure; never recreate an empty active project or return false success. A pre-intent failure changes nothing. This is local crash recovery, not background ERP activity.

Trash retains the folder for **at least 30×24 hours from deleted_at**. Purge at/after that UTC boundary on the next app-start/explicit maintenance opportunity (injected clock); an offline machine may purge later, never earlier. Remove only the recorded owned trash directory after containment checks; do not delete a same-name replacement. App-level minimal tombstone/idempotency digest survives purge so a retry cannot execute deletion twice. No financial content or typed name in that tombstone. Copies the user saved outside the project remain; the confirmation UI must say this. No trash-browse/recover endpoint is implied by this section; backup restore is a separate still-to-be-hardened contract. Samples follow the same confirmation and retention rules as real projects.

## 3. Audit integrity
audit_log hash chain (doc 02); S14 "Verify" recomputes the chain; a break → banner, exports blocked, restore guidance shown, incident note auto-drafted in logs. Findings workflow, locks, waivers, settings/threshold changes, mapping changes, imports, exports are all audited with before/after.

## 4. Hostile input (P18)
Files: size/row caps (doc 06), parser in streaming mode, XLSX zip-bomb guard (expanded-size cap, sheet/row caps), no macro execution ever (openpyxl data-only), file names sanitised before path use. Text: descriptions/vendor names escaped in UI, API JSON, Excel (formula-injection prefix, doc 09 §5), PPT, logs, and AI prompts (doc 11 §3). SQL: parameterised everywhere (store layer lint + injection tests with hostile account names). Paths: all user-supplied paths resolved under allowed roots (project folder / chosen export folder) — traversal attempts → ERR with hint.

## 5. Secrets
AI key in OS keyring (keyring lib) or env var; never in settings.json, DB, logs, exports, or diagnostics bundles (diagnostics = logs + versions + hashes, with financial values redacted by the logger's redaction filter, tested). Connector secrets follow the same rule with one addition: the **MSAL token cache** (access + refresh tokens) and any client secret live only in the OS keyring under `fpa/<project_id>/connector/*`; `GET /projects/{id}/connector` never returns them; the logger's redaction filter also masks token-shaped strings (`eyJ…` JWT prefix, `Bearer …`, `client_secret=…`, `code=…` in URLs) and `connector_pulls.error_detail` is written through the same filter; *Disconnect* deletes the keyring entries; backups (doc 16) never contain them because they were never in the project folder.

## 6. Supply chain (P17)
Pinned versions + lockfiles committed (pip + npm); licence allowlist (MIT/BSD/Apache-2.0/PSF; copyleft requires ADR); SBOM-lite generated at build (scripts/build) listing name/version/licence; no binary blobs committed; installer built from source in CI-equivalent script, payload-audited (no project data, no keys) before release (doc 16).

## 7. Privacy & advisory
Vendor/personal names appear only where operationally needed (findings, drill). AI payload minimisation per doc 11 §4. Exports carry the advisory disclaimer (doc 01 §8). Retention/deletion = project folder deletion; "Delete project" in S02 uses the exact-name confirmation, private trash and ≥30-day retention/purge of §2.1 (audited in the app-level log); it does not promise immediate erasure or erase separately saved copies.

## 8. Security tests (doc 14)
Socket-blocked full run; injection suite (SQL/formula/prompt/path); hostile-file corpus (doc 06 §7 + zip bomb + 1M-row sheet); audit-tamper detection; API token/CORS checks; secret-scan + telemetry-scan in scripts/check (no skipped gates). Connector-specific (all against `tools/mock_d365.py`): allow-list test (a profile pointing at a non-allow-listed host → ERR-113 before any socket is opened; a redirect to another host is refused); plain-`http://` base URL rejected; token-redaction test (a synthetic JWT and `client_secret=` injected into a failing request must not appear in logs, `connector_pulls`, job payloads or the diagnostics bundle); keyring-only test (grep of the project folder and DB after sign-in finds no token); state/PKCE tests (missing/wrong/expired/replayed state and foreign Host rejected before exchange; 299s accepted, 300s expired; simultaneous replay exchanges at most once; callback query never logged; application endpoints still reject absent token); hostile-payload test (a mock page carrying formula-injection strings and 10 MB cells lands quarantined/escaped exactly like a hostile file); disconnect test (keyring entries gone, settings kept, audit row written).
