# 06 — IMPORT & SOURCE-MAPPING SPECIFICATION

> Owner of: file → trustworthy gl_rows. Principles P12 (all-or-nothing), P13 (nothing silently discarded), P18 (hostile content).

## 1. Supported inputs
**Two ways in, one pipeline.** (i) Files the analyst drops (below). (ii) **Snapshot workbooks written by the Dynamics 365 connector** (doc 26 §8, DEC-013): `.xlsx` with one sheet per source in the exact `D365FO-*`/`D365BC-*` preset header shapes, all cells text, sorted by the ERP's stable key, plus a `Meta` sheet (skipped by the mapper). From stage 1 onward the connector snapshot is indistinguishable from a dropped file — same batch identity (§3), same presets, same quarantine, control totals, TB gate, supersede and audit. `import_batches.source` records `file|connector` and `pull_id` links the pull (doc 02).

CSV/TSV (encoding: UTF-8/BOM, UTF-16, Latin-1 detected; delimiter sniffed `, ; \t |`), XLSX (openpyxl read-only; every sheet listed in the import report — used or explicitly skipped by the analyst, never silently). Max 200 MB/file, 1M rows/file (ERR-021 beyond). Unsafe files (decompression ratio > 100:1, path traversal in member names, macros, external links) → ERR-029 before any parsing (doc 12 §4). Source kinds: `gl`, `budget`, `subledger` (bank/payroll/AP-AR extracts landing in the same GL shape; `subledger_kind=ap` additionally drives vendor enrichment, step 9), `drivers`, `opening` (opening BS balances), `masters`, `tb_check` (an ERP trial-balance export used only to tie out a period per account — never creates gl_rows; doc 26 §5 `D365FO-TB v1`/`D365BC-TB v1`). Formula cells: cached value used and flagged `formula_cells:N` in the report; missing cached value → quarantined row with reason.

## 2. Pipeline (each stage persisted; resumable; UI = S03 wizard)
1. **Stage:** file copied to `imports/<sha256>.<ext>` (the connector writes its snapshot directly to this path and skips the copy), batch created, raw rows stored verbatim (`import_rows_raw`) with sheet + 1-based row number.
2. **Profile:** per column — guessed type, null %, distinct count, 5 sample values (samples are data, rendered escaped).
3. **Map:** saved profile auto-applies on header match ≥ threshold; else deterministic suggestions (normalised header similarity against canonical names/synonyms, e.g. `Amt`, `Value`, `₹` → amount) ranked with confidence; analyst confirms. AI suggestion (doc 11) may reorder, never auto-apply. Mapping profiles are versioned; month-2 reuse is the default path (P11).
4. **Transform:** debit/credit column pairs → signed amount; `sign_flip` for credit-normal extracts; dates parsed against the profile's declared format(s) — ambiguous dates (both dd/mm and mm/dd plausible) quarantined, never guessed; amounts parsed via money.py (thousands separators, parentheses-negatives, currency symbols stripped and recorded). Closed transform list (profile JSON `transforms[]`): `constant:<value>` (e.g. entity for per-company exports) · `keep_text` (leading zeros) · `sign_flip` · `debit_credit_pair` · `tally_dr_cr` · `concat:<sep>` · `split:<field>:<n>` (segmented strings such as the D365 `Ledger account` `601200-IN01-022-`: segment *n* of the declared separator; the profile records the segment order once; the untouched source string is stored in `gl_rows.source_account_ref`) · `conditional:<column>=<value>` (map only when another column has a value — BC `Source No.` as vendor only when `Source Type` = `Vendor`) · `date_format:<pattern>`. Unknown transform name → ERR-022 at profile save.
5. **Validate (per row; batch → `validated` when the stage completes with zero blocking issues — quarantined rows do not block, missing required mappings and ERR-023 do):** required canonical fields present; account/entity codes resolve to master data (unknown → quarantine with "add to master data?" action that creates + remaps in one flow); posting_date inside the batch period ± cut-off window setting; posting layer (when mapped) ∈ `import.posting_layers` (default `Current`; anything else → `OUT_OF_SCOPE_LAYER`, listed with the layer name so a Tax/Custom-layer entry is a conscious exclusion, not a silent one); voucher balance check queued for commit stage. Output: valid set + quarantine set, counts reconcile exactly: `in = valid + quarantined` — displayed everywhere the batch is shown.
6. **Control totals:** analyst may enter (or file may carry) declared row count / debit total / credit total — **or attach an ERP trial-balance export (`tb_check` shape) as per-account declared movements**; mismatch vs staged = ERR-023 (details: declared vs actual per batch, and per account when a TB file was attached), commit blocked, staging kept. Per-account tie-out catches the silent-row-loss and wrong-filter mistakes a batch total cannot.
7. **Commit (atomic):** one transaction — gl_rows inserted in batches of 1,000 (multi-row INSERT; attempt #4 DEF-030: no row-by-row), master-data additions, batch status, audit. Crash/kill mid-commit → transaction rolls back, batch stays `validated` — the state it entered commit from (doc 23 §2); an integration test kills the process mid-commit and asserts zero `gl_rows` for the batch and status `validated`. Re-import of the same file hash for the same period → previous batch `superseded`, replaced atomically; row count after must equal new file, never double (idempotency test).
8. **Trial-balance gate:** per entity debit = −credit (doc 03 §2). Failure = ERR-024 with account-level drill; statements/BvA screens show a blocking banner until balanced or owner-waived (audited note).
9. **Vendor enrichment (post-commit, optional, re-runnable):** when an AP sub-ledger batch (`subledger_kind=ap`) exists for the same entity and period, GL rows **without** a vendor whose `(voucher_no, posting_date)` match exactly one AP row receive that row's vendor (`gl_rows.vendor_source = ap_match`); rows with a vendor from a mapped column (`vendor_source = column`) are never overwritten; ambiguous (many-to-one) and unmatched counts are reported on the batch and in the audit row. Needed because the D365 F&O voucher-transactions export carries no vendor (doc 26 §5) and seven rules depend on one (doc 44 §0). Triggered automatically after either batch commits (setting `import.auto_vendor_enrichment`, default on) and from `POST /imports/{batch_id}/enrich`.

## 3. Deterministic identity
`gl_row_id = SHA256(batch_id + "|" + sheet + "|" + row_no)` truncated 32 hex. `batch_id = bat_ + SHA256(file_sha256 + period_id + source_kind)[:12]`. Same file + period → same batch → re-import replaces, never duplicates. For connector snapshots `file_sha256` is the **content hash** of the data sheets (header + rows, canonical text), not of the .xlsx bytes — so an unchanged ledger pulled twice yields the same batch id and the pipeline answers "no change" (doc 26 §8.4 step 6) even though openpyxl's zip timestamps differ.

## 4. Quarantine reasons (closed list; UI groups by these)
`MISSING_REQUIRED`, `BAD_DATE`, `AMBIGUOUS_DATE`, `BAD_AMOUNT`, `UNKNOWN_ACCOUNT`, `UNKNOWN_ENTITY`, `UNKNOWN_COST_CENTRE`, `UNKNOWN_VENDOR` (only when the profile maps the column and the setting `import.require_known_vendor` is on; default off → vendor stored as text label), `OUT_OF_PERIOD`, `OUT_OF_SCOPE_LAYER` (posting layer not in `import.posting_layers`; the layer name is kept on the quarantined row), `BAD_SEGMENT` (a `split:` transform found fewer segments than the declared position), `NO_CACHED_FORMULA_VALUE`, `DUPLICATE_ROW_IN_FILE` (exact-hash dupes flagged, kept once), `EMPTY_ROW` (counted, not stored). Row-level problems are quarantine reasons, never ERR codes (doc 22 §3). Each carries a plain-language explanation + the fix action (doc 13 copy).

## 5. Duplicate & overlap handling
Within-file exact duplicates: flagged, analyst chooses keep-one (default) / keep-all (audited). Cross-batch overlap (same voucher+account+amount+date in a committed batch): not blocked — surfaced to EXC-002 at rule stage, since legitimate corrections exist. The import report shows overlap counts before commit so the analyst decides informed.

## 6. Performance posture
Streaming parse (no whole-file DOM); 250k-row GL commit ≤ 60s on doc-14 reference profile; profiler samples first 5k rows for stats but validates all rows.

## 7. Fixtures owned here
Coherent corpus + malformed corpus (≥10 files: bad encoding, missing column, ambiguous dates, unbalanced voucher file, duplicate file, formula-without-cache XLSX, 0-byte, wrong-delimiter, parentheses-negatives, mixed sign conventions, short-segment ledger account) each with `expected.json` (counts by quarantine reason) + the ERP-shape files of doc 42 §4 (`sample-data/erp_shapes/`) with their parity expectations (same committed rows as the CSV shape; 3 `Tax`-layer rows → `OUT_OF_SCOPE_LAYER`; AP enrichment fills every vendor; TB tie-out zero differences). Generator spec: MASTER_PLAN §6 — one plan, controlled noise, plants only from answer key, computed balancing legs, fixed seed, byte-identical regeneration hash-tested.

DEC-024 retention (24 §6, 02 §5.2): retain each captured GL row plus its authentic raw sheet/row identity and origin; keep the batch identity hash distinct from the connector workbook byte hash. A later vendor-enrichment write creates a different retained image, never rewrites historical source content. Full file retention/membership publication remains WI-0001 work.
