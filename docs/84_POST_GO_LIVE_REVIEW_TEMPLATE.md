# 84 — POST-GO-LIVE REVIEW (30/60/90 days, then per release)

Template (fill per doc 87; metrics from the product itself wherever possible): Adoption (closes completed in-app, spreadsheet retired?) · Speed (close cycle days + analyst hands-on trend vs baseline — the core promise, charted) · Quality (S1/S2 count, restatements, checks failures, acceptance on live-shaped data) · Findings (volume, closure rate, waiver rate + reasons themes — are rules helping or noisy? threshold DEC proposals) · Forecast (FVA trend by group; method changes) · Support (tickets by theme → doc/UX fixes) · User voice (analyst + CFO quotes, top-3 friction) · Decisions (DEC list: thresholds, scope, next-phase priorities) · Actions with owners/dates. Filed in evidence/ (doc 77); the 90-day review is the input gate for Phase-2 prioritisation (17).


## Metric definitions (so reviews are comparable across clients/releases)
Close cycle days: period end → sign-off timestamp (business days, doc 30 calendar). Analyst hands-on: self-timed by the analyst with the in-app session timer (start/pause on S01 during close; honest self-reporting is a pilot-agreement item). Findings precision: % of findings the analyst marked explained/corrected vs waived-as-not-relevant (waivers with reason "not an issue" count against precision; target ≥70% by the 90-day review, else threshold/rule tuning DEC). Pack challenge count: numbers challenged in CFO review that could not be drilled live (target 0). Forecast trust: groups where the recommended method beat naive over the quarter (doc 74).
