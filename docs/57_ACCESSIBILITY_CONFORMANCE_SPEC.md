# 57 — ACCESSIBILITY CONFORMANCE SPECIFICATION (WCAG 2.2 AA)

Per-criterion conformance targets (audit method in doc 34 AUD-H): Perceivable — text alternatives for charts (data-table toggle on every chart, 53), contrast ≥4.5:1 text / 3:1 large+UI (token pairs tested in CI), resize 200% without loss (13), no colour-only meaning (P19, word+icon chips). Operable — full keyboard map per screen (published in Help: global: g then d/i/s/b/e/f/x for nav, / focuses filter, ? opens shortcut overlay), visible focus ring (token), no keyboard traps (dialog focus trap + Esc), timing: jobs never auto-dismiss critical errors. Understandable — labels+instructions on all inputs, error identification in text with suggestion (22 copy), consistent navigation/help. Robust — semantic landmarks, aria-live polite announcements for job completion and finding counts, table header associations; axe-core zero critical/serious on every screen is a Wave-4 gate. Known limitations declared honestly in the conformance statement shipped in-app (S15): charts' sonification not provided; PDF exports are print-oriented (data tables in Excel are the accessible artefact). Conformance statement reviewed each release (16 checklist).


## Screen-by-screen conformance checklist (Wave-4 evidence per screen, AUD-H)
Every screen must evidence, with an artefact in evidence/: (1) tab order follows visual order, skip-to-content present; (2) all actions keyboard-reachable, shortcut overlay (?) lists them; (3) tables have captions + scoped headers, sortable headers are buttons with aria-sort; (4) every chart exposes a "View as table" toggle rendering the same numbers; (5) job completion / findings count / lock state announced via aria-live polite (assertive only for ERR-090); (6) focus returns to the invoking control after dialogs/drawers; (7) 200% zoom without clipped actions; (8) reduced-motion disables chart/drawer animation; (9) greyscale printing stays legible (words carry meaning). Missing any item = not done (doc 14 §6).
